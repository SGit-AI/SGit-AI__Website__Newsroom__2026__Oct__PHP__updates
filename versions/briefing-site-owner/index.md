Updating plugins does not fix it. If someone hosts the site for you, ask them in writing whether PHP has been updated to a fixed version and restarted. If you run the server yourself, update PHP today. Read the site as Casey → You do not need to understand the bug to deal with it. What you need is to know whose job the update is, and the exact question to ask. This page gives you both. ## What to decide or do - **Find out whether your site runs on PHP.** WordPress, WooCommerce, Drupal, Joomla, Magento, PrestaShop, Moodle and most hosting control panels do. If you are not sure, ask whoever built the site. - **Updating WordPress, plugins or themes does not fix this.** The flaw is in PHP itself, one layer down. It has to be fixed on the server. - **If someone hosts the site for you**, send them this, in writing: *Has PHP on the server running my site been updated to 8.5.12, 8.4.27, 8.3.36 or 8.2.35, or to your distribution's fixed package, and have the PHP processes been restarted since? The step-by-step list has the temporary settings for a server you cannot update straight away. - **If your site is on PHP 8.1 or older**, there is no ready-made fix. Ask your developer or host about moving to a supported version now; it is overdue anyway. - **Keep calm about being hacked.** No organisation has confirmed a break-in as of the latest capture.
